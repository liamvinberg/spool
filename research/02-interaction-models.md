## 1. Figma Prototyping

### 1.1 Triggers

Figma's help center and its Plugin API (`Trigger` type) independently enumerate the same **12 triggers**, cross-validated one against the other:

| Help-center name | API `type` | Extra fields | Behavior |
|---|---|---|---|
| On click / On tap | `ON_CLICK` | — | Desktop click or mobile tap |
| While hovering | `ON_HOVER` | — | Fires while cursor is over hotspot; **auto-reverts** when cursor leaves |
| While pressing | `ON_PRESS` | — | Fires on click-and-hold / tap-and-hold; **auto-reverts** on release |
| On drag | `ON_DRAG` | — | Fires during drag in any of 4 directions (swipe, drag-to-refresh, bidirectional transitions) |
| Mouse enter | `MOUSE_ENTER` | `delay`, `deprecatedVersion` | One-way (non-reverting), fires once on entry |
| Mouse leave | `MOUSE_LEAVE` | `delay`, `deprecatedVersion` | One-way, fires once on exit |
| Mouse down (touch down) | `MOUSE_DOWN` | `delay` | One-way, initial press |
| Mouse up (touch up) | `MOUSE_UP` | `delay` | One-way, on release |
| After delay | `AFTER_TIMEOUT` | `timeout` (ms) | Only trigger requiring no user input |
| Key/Gamepad | `ON_KEY_DOWN` | `device: "KEYBOARD"\|"XBOX_ONE"\|"PS4"\|"SWITCH_PRO"\|"UNKNOWN_CONTROLLER"`, `keyCodes: number[]` | Keyboard or named gamepad, single key or combo |
| When video hits | `ON_MEDIA_HIT` | `mediaHitTime` | Only on connections starting from a video node |
| When video ends | `ON_MEDIA_END` | — | Only on video connections |

Sources: [Prototype triggers](https://help.figma.com/hc/en-us/articles/360040035834-Prototype-triggers), [Trigger – Developer Docs](https://developers.figma.com/docs/plugins/api/Trigger/).

- **Mutual-exclusion rule**: only one of {On click/tap, While hovering, While pressing, Mouse enter, Mouse leave, Mouse down, Mouse up, After delay, When video ends} may be set per object; Key/Gamepad, On drag, and When-video-hits can be stacked/repeated on the same object. You also cannot combine On click/On tap with While hovering on the same element. — [Prototype triggers](https://help.figma.com/hc/en-us/articles/360040035834-Prototype-triggers), [Connect your prototype](https://help.figma.com/hc/en-us/articles/360040315773-Connect-your-prototype)
- **Dated changelog note** (rare explicit date in Figma's docs): "interactions created before November 16, 2023 are now labeled Mouse move inside. Mouse move inside interactions can no longer be created. All new interactions have the Mouse enter trigger" (Mouse enter now fires only on initial entry, not on every internal move). — [Prototype triggers](https://help.figma.com/hc/en-us/articles/360040035834-Prototype-triggers)
- **No native double-click, double-tap, or right-click trigger.** Confirmed by omission from the official list; corroborated by a still-open community feature request. UNCONFIRMED whether this has changed very recently. — [Figma Forum](https://forum.figma.com/suggest-a-feature-11/right-click-and-double-click-triggers-for-prototypes-10499)
- Available on any plan, including free, to anyone with edit access. — [Prototype triggers](https://help.figma.com/hc/en-us/articles/360040035834-Prototype-triggers)
- **Not part of core Design prototyping**: Figma Sites (a separate product) has its own, similarly-named but distinct interaction system (Reveal, Scroll parallax, Cursor effect, Marquee, Lightbox, Spin, Typewriter, Scramble text, Draggable, Hover effect, Press effect). Only `Change to`, `Back`, `Scroll to`, `Conditional`, and `Set variable` overlap with core prototyping — do not conflate the two systems. — [Add interactions to an element (Figma Sites)](https://help.figma.com/hc/en-us/articles/31242843431575-Add-interactions-to-an-element)

### 1.2 Actions

**Key data-model finding**: the help center presents ~14–15 named "actions," but Figma's Plugin API `Action` type is actually a discriminated union of only **8 top-level variants** — most help-center "actions" are just parameter values within two of them (`NODE` and `UPDATE_MEDIA_RUNTIME`). "Instant" transition is represented as `transition: null`, not a distinct type. Source: [Action – Developer Docs](https://developers.figma.com/docs/plugins/api/Action/).

```
type Action =
  | { type: "BACK" | "CLOSE" }
  | { type: "URL"; url: string }
  | { type: "UPDATE_MEDIA_RUNTIME"; mediaAction: "PLAY"|"PAUSE"|"TOGGLE_PLAY_PAUSE"|"MUTE"|"UNMUTE"|"TOGGLE_MUTE_UNMUTE"; destinationId: string|null }
  | { type: "UPDATE_MEDIA_RUNTIME"; mediaAction: "SKIP_FORWARD"|"SKIP_BACKWARD"; amountToSkip: number }
  | { type: "UPDATE_MEDIA_RUNTIME"; mediaAction: "SKIP_TO"; newTimestamp: number }
  | { type: "SET_VARIABLE"; variableId: string|null; variableValue?: VariableData }
  | { type: "SET_VARIABLE_MODE"; variableCollectionId: string|null; variableModeId: string|null }
  | { type: "CONDITIONAL"; conditionalBlocks: ConditionalBlock[] }
  | { type: "NODE"; destinationId: string|null; navigation: "NAVIGATE"|"SWAP"|"OVERLAY"|"SCROLL_TO"|"CHANGE_TO";
      transition: Transition|null; preserveScrollPosition?: boolean; overlayRelativePosition?: Vector;
      resetVideoPosition?: boolean; resetScrollPosition?: boolean; resetInteractiveComponents?: boolean }
```

| Help-center name | API shape | Notes |
|---|---|---|
| Navigate to | `NODE`, `navigation:"NAVIGATE"` | Frame-to-frame; carries `transition` + reset flags |
| Back | `{type:"BACK"}` | No parameters; returns via navigation history |
| Open overlay | `NODE`, `navigation:"OVERLAY"` | See overlay config below |
| Close overlay | `{type:"CLOSE"}` | Dismisses current overlay |
| Swap overlay | `NODE`, `navigation:"SWAP"` | Replaces one overlay with another, **inheriting** the original's position/settings; **not recorded in navigation history** (Back skips over it) |
| Scroll to | `NODE`, `navigation:"SCROLL_TO"` | Instant or `SCROLL_ANIMATE` transition; can target nested scroll containers |
| Change to | `NODE`, `navigation:"CHANGE_TO"` | Variant switch; only available with interactive components; usable on a nested instance to change a parent's variant |
| Open link | `{type:"URL"; url}` | Always opens in a new browser tab with a "leaving Figma" notice; no separate new-tab toggle |
| Set variable | `{type:"SET_VARIABLE"}` | String/Number/Boolean support full expressions; Color does not |
| Set variable mode | `{type:"SET_VARIABLE_MODE"}` | Page-scoped; cascades only to objects with mode set to "Auto" |
| Conditional (If/Else) | `{type:"CONDITIONAL"; conditionalBlocks:[]}` | Array-typed field suggests possible multi-block/else-if support; exact per-block shape UNCONFIRMED (`ConditionalBlock` API page 404s) |
| Play/Pause/Toggle video | `UPDATE_MEDIA_RUNTIME` | — |
| Mute/Unmute/Toggle video | `UPDATE_MEDIA_RUNTIME` | — |
| Set to specific time | `UPDATE_MEDIA_RUNTIME`, `SKIP_TO` | — |
| Skip forward/backward | `UPDATE_MEDIA_RUNTIME`, `SKIP_FORWARD`/`SKIP_BACKWARD` | — |

Sources: [Prototype actions](https://help.figma.com/hc/en-us/articles/360040035874-Prototype-actions), [Create overlays in your prototypes](https://help.figma.com/hc/en-us/articles/360039818254-Create-overlays-in-your-prototypes), [Action – Developer Docs](https://developers.figma.com/docs/plugins/api/Action/).

**Transitions attached to `NODE` actions** (`Transition` type — two discriminated sub-shapes):
```
SimpleTransition      { type:"DISSOLVE"|"SMART_ANIMATE"|"SCROLL_ANIMATE"; easing; duration }
DirectionalTransition { type:"MOVE_IN"|"MOVE_OUT"|"PUSH"|"SLIDE_IN"|"SLIDE_OUT"; direction:"LEFT"|"RIGHT"|"TOP"|"BOTTOM"; matchLayers:boolean; easing; duration }
```
Instant = `transition:null`. `matchLayers` is an API-only field with no clear help-center explanation found — UNCONFIRMED exact UI meaning. Source: [Transition – Developer Docs](https://developers.figma.com/docs/plugins/api/Transition/), [Prototype animations](https://help.figma.com/hc/en-us/articles/360040522373-Prototype-animations).

**Overlay configuration** (`Overlay` type): position is one of 7 fixed anchors (`CENTER`, `TOP_LEFT/CENTER/RIGHT`, `BOTTOM_LEFT/CENTER/RIGHT`) or `MANUAL` (uses `overlayRelativePosition`); background is `{type:"NONE"}` or `{type:"SOLID_COLOR"; color}` (scrim); `OverlayBackgroundInteraction` is `"NONE"` or `"CLOSE_ON_CLICK_OUTSIDE"`. Source: [Overlay – Developer Docs](https://developers.figma.com/docs/plugins/api/Overlay/), [Create overlays in your prototypes](https://help.figma.com/hc/en-us/articles/360039818254-Create-overlays-in-your-prototypes).

**Scroll/overflow setup** (context for Scroll to): overflow direction per frame is vertical/horizontal/both/none; per-object scroll behavior is Scroll with parent / Fixed / Sticky. — [Prototype scroll and overflow behavior](https://help.figma.com/hc/en-us/articles/360039818734-Prototype-scroll-and-overflow-behavior)

### 1.3 Variables System

**Types.** The current UI names **six** variable types: Color, Number, String, Boolean, Timing, Easing. — [Overview of variables, collections, and modes](https://help.figma.com/hc/en-us/articles/14506821864087-Overview-of-variables-collections-and-modes)

**Discrepancy flag**: the Plugin/REST API's `VariableResolvedDataType` enum has only **4 values** — `BOOLEAN | FLOAT | STRING | COLOR`. Timing and Easing don't appear as `resolvedType` values in either API reference. These two are tied to **Figma Motion**, which is in open beta as of **June 24, 2026** (~4 weeks before this research) — the public API docs appear not yet updated to expose them, and the classic Set-variable action only documents operations for the 4 core types. Treat Timing/Easing as new, motion-specific, and in flux. Sources: [Explore Figma Motion](https://help.figma.com/hc/en-us/articles/41274629073303-Explore-Figma-Motion), [What's new from Config 2026](https://help.figma.com/hc/en-us/articles/39582753756695-What-s-new-from-Config-2026), [developers.figma.com/docs/plugins/working-with-variables/](https://developers.figma.com/docs/plugins/working-with-variables/), [REST API variables endpoints](https://developers.figma.com/docs/rest-api/variables-endpoints/).

**Scoping** (`VariableScope`, 22 values, grouped by type) — governs which UI fields a variable can be bound to:
- **Number (FLOAT)**: ALL_SCOPES, TEXT_CONTENT, CORNER_RADIUS, WIDTH_HEIGHT, GAP, OPACITY, STROKE_FLOAT, EFFECT_FLOAT, FONT_WEIGHT, FONT_SIZE, LINE_HEIGHT, LETTER_SPACING, PARAGRAPH_SPACING, PARAGRAPH_INDENT
- **Color**: ALL_SCOPES, ALL_FILLS, FRAME_FILL, SHAPE_FILL, TEXT_FILL, STROKE_COLOR, EFFECT_COLOR
- **String**: ALL_SCOPES, TEXT_CONTENT, FONT_FAMILY, FONT_STYLE
- **Boolean**: used for layer visibility per help docs, but no Boolean-specific scope constant appears in the enum — UNCONFIRMED whether it's `ALL_SCOPES`-only.
Scopes are a UI-decluttering affordance (which fields *show* the variable as an option), not a hard technical restriction. Sources: [VariableScope – Developer Docs](https://developers.figma.com/docs/plugins/api/VariableScope/), [Apply variables to designs](https://help.figma.com/hc/en-us/articles/15343107263511-Apply-variables-to-designs).

**Collections**: "a set of variables and modes." Schema fields: `id, name, key, modes[], defaultModeId, variableIds[], remote, hiddenFromPublishing` (extended collections add `parentVariableCollectionId, rootVariableCollectionId, inheritedVariableIds, localVariableIds, variableOverrides, deletedButReferenced`). "Extending" a collection (inheriting across a library boundary) is Enterprise-plan-only — mechanics UNCONFIRMED beyond this. Sources: [Overview of variables, collections, and modes](https://help.figma.com/hc/en-us/articles/14506821864087-Overview-of-variables-collections-and-modes), [REST API variables endpoints](https://developers.figma.com/docs/rest-api/variables-endpoints/), [developers.figma.com/docs/plugins/working-with-variables/](https://developers.figma.com/docs/plugins/working-with-variables/).

**Modes**: "a list of values for a variable in a collection, storing one value per variable" (one column of values per context). Documented use cases: theming (light/dark/high-contrast/colorblind), localization (copy-length testing), responsive sizing (watch/mobile/desktop spacing). Available on Education, Professional, Organization, Enterprise plans. — [Modes for variables](https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables)

**Aliasing**: variables can reference other variables (`VariableAlias { type:'VARIABLE_ALIAS'; id }`) — the mechanism behind design-token aliasing. — [VariableAlias – Developer Docs](https://developers.figma.com/docs/plugins/api/VariableAlias/)

**Expressions/conditionals**: usable only in **Set variable** (Number/String/Boolean, not Color) and **Conditional** actions.
- Operators: numeric `+ - * /`; string concatenation `+`; comparison `== != > < >= <=`; logical `and`, `or`, `!`/`not`.
- Order of operations: parentheses → multiplication/division → addition/subtraction (math); comparisons before logical operators (booleans).
- Conditional action: one **If** expression + action(s), optional **Else** action(s); invalid expressions are outlined in red live. The `conditionalBlocks` field is an *array* at the schema level, suggesting possible else-if chaining beyond what the UI prose describes — UNCONFIRMED (`ConditionalBlock` type page 404s).
- No documented functions, loops, or array/list operators.
Sources: [Use expressions in prototypes](https://help.figma.com/hc/en-us/articles/15253194385943-Use-expressions-in-prototypes), [Multiple actions and conditionals](https://help.figma.com/hc/en-us/articles/15253220891799-Multiple-actions-and-conditionals).

| Modes/collection (Professional) | up to 10 | [What's new from Config 2026](https://help.figma.com/hc/en-us/articles/35794667554839-What-s-new-from-Config-2026) |

### 1.4 Smart Animate

**Layer matching**: matches by **layer name + hierarchical position** — not any other ID. Duplicating a frame (rather than recreating it) is the recommended way to guarantee matching names. Layer stacking order matters (a higher-stacked layer animates above destination content, risking overlap). Layers nested in **differently-named groups will not match** across frames — grouping is the documented technique to deliberately scope/break matching. If a layer has no match in the destination, it dissolves into view. If a layer's properties are identical between frames, it isn't animated at all (useful for persistent chrome). — [Smart animate layers between frames](https://help.figma.com/hc/en-us/articles/360039818874-Smart-animate-layers-between-frames)

**What it CAN animate** — the official list is exactly **5 properties, verbatim, no more**: **Scale, Position, Opacity, Rotation, Fill** (solid/gradient/image). — same source (verified via direct verbatim search of the page; corner radius, text content, and vector/path morphing are not mentioned anywhere in the article).

**What it explicitly CANNOT animate**: drop/inner shadows (dissolve fallback); "moving between shapes" (different shape types); texture/noise effects and background/layer blur (supported only if frames are literal duplicates, since these are per-instance randomized). Overlays generally don't get Smart Animate (Figma treats overlay-opens as new frames) *except* when swapping between two overlays with matching layers. Layers with "Fix position when scrolling" go into a separate "Fixed layers" list handled differently. — same source

**Practitioner-observed gap vs. docs (flag: undocumented behavior, not officially confirmed)**: community reports suggest corner-radius interpolation actually happens in practice (with pixelation bugs at extreme values like 9999), while vector/path morphing does not work at all (confirmed by a still-open Figma feature request). Auto Layout + Smart Animate combinations are separately reported as buggy (content jump/scroll-reset). — [FigAnimations guide](https://www.figanimations.com/blogs/the-complete-guide-to-smart-animate-in-figma) (undated), [Figma Forum: vector animation feature request](https://forum.figma.com/suggest-a-feature-11/support-vector-animations-in-smart-animate-11380), [Figma Forum: corner radius pixelation](https://forum.figma.com/ask-the-community-7/fix-corner-radius-becomes-pixelated-when-using-smart-animate-13580), [Figma Forum: auto layout bug thread](https://forum.figma.com/t/auto-layout-doesnt-smart-animate-between-auto-layout-frames-bug-or-feature/6712) — all UNCONFIRMED for exact currency.

**Easing (bezier family, 8 named options)**: Linear, Ease In, Ease Out, Ease In And Out, Ease In Back, Ease Out Back, Ease In And Out Back, and Custom (4-point cubic bezier, expressible as CSS `cubic-bezier(x1,y1,x2,y2)`). No numeric bezier coordinates published for the named presets. No distinct "bounce" bezier preset exists — bounce-like motion only comes from the spring system. — [Prototype easing and spring animations](https://help.figma.com/hc/en-us/articles/360051748654-Prototype-easing-and-spring-animations)

**Spring/physics easing (5 named presets)**: Gentle, Quick, Bouncy, Slow, Custom. Custom spring exposes exactly three parameters, no numeric ranges/defaults published: **Stiffness** (number of bounces), **Damping** (level of spring), **Mass** (speed of animation and bounce height — adjusting mass also changes the derived duration-in-ms; duration is a read-only *output* of spring params, not an independent input). API schema (`Easing` type) additionally exposes `easingFunctionSpring: { mass, stiffness, damping, initialVelocity }`. — [Prototype easing and spring animations](https://help.figma.com/hc/en-us/articles/360051748654-Prototype-easing-and-spring-animations), [Easing – Developer Docs](https://developers.figma.com/docs/plugins/api/Easing/) (via Transition page)

### 1.5 Interactive Components

**Definition**: "Interactive components allow you to create prototype interactions between variants in a component set. Any time you add an instance to your designs, those interactions are set up and ready to go." — [Create interactive components with variants](https://help.figma.com/hc/en-us/articles/360061175334-Create-interactive-components-with-variants); a newer doc states it more simply as prototype connections added directly inside a component set — [Interactive components fundamentals](https://help.figma.com/hc/en-us/articles/39747190144023-Components-collection-Interactive-components-fundamentals)

**Not a separate primitive**: interactive components are prototype connections (trigger→action edges) authored between existing variants inside a component set; wiring it once at the component-set level means every instance carries the connections, instead of rewiring per-instance (documented worked example: 32 duplicate frames / 160 manual connections collapsed to 1 component set with 2 variants / 2 connections). The **"Change to"** action is what performs the variant switch, and can be applied on a nested instance to change its parent's variant. Worked button example: `While hovering` → `Change to` (hover variant) → `Smart animate`, 150ms; separate connections handle Mouse down/up/leave — using no Variables at all. Sources: [Create interactive components with variants](https://help.figma.com/hc/en-us/articles/360061175334-Create-interactive-components-with-variants), [Prototype actions](https://help.figma.com/hc/en-us/articles/360040035874-Prototype-actions), [Design an interactive button component](https://help.figma.com/hc/en-us/articles/20953528101783-Design-an-interactive-button-component).

**Interplay with Variables/conditionals** (bidirectional):
- A variant change can drive a variable ("The variable updates, which in turn updates any other elements bound to that same variable").
- A variable can drive which variant is shown (variant/instance-swap properties can be bound to variables).
- Conditional actions (if/else) can sit on top, e.g. a required-checkbox gate or a `Set variable: itemsSelected = itemsSelected + 1` counter.
Sources: [Create interactive components with variants](https://help.figma.com/hc/en-us/articles/360061175334-Create-interactive-components-with-variants), [Use variables in prototypes](https://help.figma.com/hc/en-us/articles/14506587589399-Use-variables-in-prototypes), [Multiple actions and conditionals](https://help.figma.com/hc/en-us/articles/15253220891799-Multiple-actions-and-conditionals), [Advanced prototyping examples](https://help.figma.com/hc/en-us/articles/17146044893591-Advanced-prototyping-examples).

**Component property types** (context): Variant, Boolean (visibility only), Text (editable text, no rich formatting), Instance-swap (nested slot + preferred values). Documented gotcha: consolidating two separately-wired components via a Boolean property **destroys existing prototype connections** ("Prototyping noodles must connect between two objects... the prototyping connections will be lost"). — [Explore component properties](https://help.figma.com/hc/en-us/articles/5579474826519-Explore-component-properties) (a note about "Simplified instances" deprecation starting March 23, 2026 surfaced in the same fetch but via AI-summarized rather than verbatim text — flag as UNCONFIRMED, precise near-term date, verify independently.)

**State persistence**: Figma "memorizes the last set variant" of an interactive component across navigation ("state memorization"); a matching component (same name+hierarchy) on a *different* top-level frame will mirror state changes too ("state sharing"), but only after first interaction. Both are disable-able per-interaction via "Reset component state" / "Reset scroll position" / "Reset video state." This system "launched May 24, 2023" (one of the few explicit in-text dates in Figma's help center). — [State management for prototypes](https://help.figma.com/hc/en-us/articles/14397859494295-State-management-for-prototypes)

### 1.6 Prototype Settings (device, flows, starting points)

**Device selection**: Figma offers preset device frames; choosing a frame preset auto-selects a matching device (overridable). Presentation view offers *all* device presets plus two special sizing modes (presentation-view-only): **Custom Size (Fit)** (auto-scales to viewer's screen) and **Presentation (Full)** (full-size, entire prototype visible). Inline preview offers **mobile presets only** (phone/watch/tablet) due to editor space constraints. No native custom device-frame/bezel import exists (community plugin "Bezel" fills this gap; a related feature request remains open). Orientation (portrait/landscape) is selectable for presentation view, but **cannot be switched within a running prototype**. A custom background color can render behind the device frame in presentation view. Anyone with edit access can adjust these settings. — [Set prototype device and background settings](https://help.figma.com/hc/en-us/articles/21158597546391-Set-prototype-device-and-background-settings), [Figma Forum: custom device frame request](https://forum.figma.com/suggest-a-feature-11/ability-to-create-custom-frame-sizes-and-prototype-devices-8676) (UNCONFIRMED currency)

**Flows / starting points**: a flow is "a collection of connected frames that make up a single prototype experience" (e.g., separate flows for account creation, browsing, checkout within one file). A flow auto-creates the first time two previously-unconnected frames are connected, with the first frame designated the starting point; starting points can also be added manually. **Constraints**: starting points can only be set on top-level frames, and **a frame can only have one flow starting point** — though a single frame *can* belong to multiple flows, and once reached via any flow, all its outgoing interactions become available regardless of entry path. Starting points render as a draggable blue flag/icon on canvas; flows default to "Flow 1," "Flow 2," etc., renamable, with optional rich-text descriptions for usability-test documentation. A dedicated Flows panel lists all starting points with jump-to. — [Create and manage prototype flows](https://help.figma.com/hc/en-us/articles/360039823894-Create-and-manage-prototype-flows) (article has been retitled at least once; content stable)

### 1.8 Documented Ceilings

**Real/functional text input — NOT natively supported.** No help.figma.com article documents a way for running-prototype logic to capture and read live keystrokes. (thread opened Aug 20, 2024, last activity Aug 22, 2024 — **~2 years stale relative to today; not independently re-confirmed for 2025/2026**, treat "still unsupported" as UNCONFIRMED-for-2026 though no contradicting evidence surfaced). ## 4. ProtoPie

Note on dating: every ProtoPie docs page fetched returned an identical "last updated" timestamp matching the exact fetch time — almost certainly a rendering artifact rather than genuine per-page modification dates. No per-page dates are cited below as a result.

### 4.1 Core model

ProtoPie names its own conceptual framework explicitly: **"Trigger, Response & Object" (TRO)** — "the heart of how ProtoPie works," based on "how objects move in the world instead of programming." — [Triggers](https://www.protopie.io/learn/docs/interactions/triggers), [Responses](https://www.protopie.io/learn/docs/interactions/responses)

**Objects**: "the layer that is impacted by an action." The concrete UI term is **Layer** (Object is the conceptual name). Documented layer types: **Shape** (Rectangle, Oval, Star, Polygon), **Media** (Image, Video, Lottie/JSON, Audio, Camera with QR/barcode scanning), **Interactive** (Text, Input — single/multi-line with native keyboard, keypad types text/URL/email/number/password), **Functional** (Background Blur). Imported and native layers both become the same Layer entity once inside ProtoPie — no formal "native vs. imported" taxonomy in the docs. Figma import (via ProtoPie's Figma plugin, ProtoPie 9.5.0+) preserves visibility/lock/position/size/rotation/opacity/constraints/fill/borders/shadow/auto-layout-core-properties; top-level Figma frames become ProtoPie scenes; multiple fills and advanced stroke settings degrade to editable SVGs; layer blur/inner shadow are dropped; components without "Component Mode" import as plain containers requiring manual conversion; reimport preserves ProtoPie-side edits (blocking resync of edited properties). Sources: [Layers](https://www.protopie.io/learn/docs/basic-features/layers), [Importing from Figma](https://www.protopie.io/learn/docs/import-importing-from-figma).

**Triggers** — six categories, confirmed both in core docs and a comparison post:

| Category | Triggers |
|---|---|
| Touch | Tap, Double Tap, Touch Down, Touch Up, Long Press, Fling, Pull, Drag, Pinch, Rotate |
| Conditional | Chain, Range, Start, Detect |
| Mouse | Mouse Over, Mouse Out |
| Key | Press |
| Input | Focus, Return |
| Sensor | Tilt, Compass, Sound, 3D Touch, Proximity, Receive, Voice Command |

Selected definitions: **Chain** — "The changes of a property of one layer changes the property of another layer"; **Detect** — "activated when a layer property or variable changes"; **Start** — "Activate interactions upon loading a certain scene." No "Timeline" trigger exists (Timeline is a per-response scheduling UI, not a trigger — see Scenes below); "Condition" is not a trigger either — it's a response type. Sources: [Triggers](https://www.protopie.io/learn/docs/interactions/triggers), [ProtoPie vs. Figma](https://www.protopie.io/blog/protopie-vs-figma).

**Flag — possibly outdated**: "3D Touch" is still listed as a live Sensor trigger, despite Apple discontinuing 3D Touch hardware starting with the iPhone XR/XS generation (2018) in favor of Haptic Touch — reads as stale relative to current hardware.

**Responses** — a flat list of **28 types** (verbatim order): Move, Scale, Rotate, 3D Rotate, Opacity, Color, Radius, Border, Shadow, Background Blur, Reorder, Scroll, Jump, Send, Link, Text, Media, Focus, Camera, Playback, Volume, Vibrate, Speak, Listen, Reset, Stop, Assign, **Condition**. Condition is confirmed as its own response ("Configuring parameters that need to be met to trigger [subsequent] responses") with **6 comparison operators: `> ≥ < ≤ = ≠`**. Several responses are layer-type-gated (Camera→Camera layers, Playback/Volume→media layers, Focus→Input layers), though the docs don't label this explicitly. — [Responses](https://www.protopie.io/learn/docs/interactions/responses)

**Variables**: **3 types** — Text, Number, Color (hex only). **2 scopes**: **"For All Scenes"** (global) and **"For This Scene"** (local; uniquely supports storing a formula inside the variable itself). Created/updated via the **Assign** response; watched via the **Detect** trigger. **Predefined variables** (auto-updating, always available): `$mouseX/Y`, `$touchX/Y`, `$touchVelocity(X/Y)`, `$touchPointerCount`, `$deviceOS`, `$deviceHeight/Width`, `$keyboardHeight`, `$pi`, `$time`, `$voiceTranscript`, `$qrValue/Height/Width/X/Y`, `$barcodeValue/Height/Width/X/Y`. — [Variables: Getting Started](https://www.protopie.io/learn/docs/variables/getting-started), [Predefined Variables](https://www.protopie.io/learn/docs/variables/predefined-variables)

**Formulas**: "expressions that allow you to add logic to your interactions" (e.g., password validation, cart totals). **Language basis is UNCONFIRMED as JS vs. custom DSL** — docs never say "JavaScript"; syntax (backtick layer references, `$variable` sigil, custom function names) reads as a custom DSL, though ProtoPie never explicitly states "not JS" either. Syntax: operators `+ - * / %`; double-quoted strings with `\n`; hex colors `#FFFFFF`; **layer references via backticks** + `.propertyName` (e.g. `` `layerName`.opacity ``); variable names limited to Latin letters/numbers/underscores; `+` also concatenates text, and text+number via `+` yields text. Built-in functions span Text (`concat`, `indexOf`, `length`, `lowerCase/upperCase`, `left/right`, `lpad/rpad`, `repeat`, `replace`, `trim/ltrim/rtrim`, `regexextract`, `regexreplace`, `parseJson`), Math (`pow`, `sqrt`, `min/max`, `abs`, `sign`, `round/floor/ceil`, `random/randomInt`, `radians/degrees`, trig functions), Color (`color`, `red/green/blue`), Type conversion (`number`, `text`, `format`), Layer (`layer`, `parent`, `initial`), Relative coordinates (`toLayerX/Y`, `toScreenX/Y`), Time/Date (`timeNow`, `time`, `hour/minute/second`, `diffTime`, `formatTime`, `dateNow`, `date`, `year/month/day`, `diffDate`, `formatDate`, `epochtodate`). — [Formulas: Getting Started](https://www.protopie.io/learn/docs/formulas/getting-started), [Formulas: Syntax](https://www.protopie.io/learn/docs/formulas/syntax), [Functions](https://www.protopie.io/learn/docs/formulas/functions)

**Scenes**: "similar to an artboard in Sketch and Adobe XD and a top-level frame in Figma." Transitions use the **Jump** response; a **Smart Jump** variant auto-animates matching objects by name/hierarchy across scenes (directly analogous to Figma's Smart Animate). Scenes reset to initial state on re-entry unless the reset option is disabled — i.e., scenes are stateful with a controllable reset-vs-persist choice. Scenes can hold scene-scoped variables. **Timelines** are a distinct, per-response visual representation of time/delay/repeat settings (draggable duration/start-delay, batch-editable; not shown for continuous triggers like Drag); a related **Valueline** represents a layer's movement range when linked to a Chain trigger. — [Scenes](https://www.protopie.io/learn/docs/basic-features/scenes), [Timelines](https://www.protopie.io/learn/docs/interactions/timelines)

**Components**: "sets of layers and interactions" reusable across a prototype — a **master component** + **instances**. Components **have their own internal variables/triggers/responses**: "Editing a main component is similar to editing a scene. You can create, modify, and delete the component's layers, variables, triggers, and responses." Master edits propagate to all instances automatically; per-instance property overrides persist even after master edits (reversible via "Reset Overrides"). A component's variable can be exposed via **"Make Overridable,"** letting each instance set its own initial value — functioning as the component's public parameter/interface. Components are otherwise **isolated** from each other and their containing scene; the **Send/Receive** system bridges this isolation via four channels: **Send to Parent**, **Send to Child Component**, **Send to Current Scene**, **Send to Current Component** (with matching Receive-trigger channels). This is scoped within a single prototype, distinct from (but sharing vocabulary with) ProtoPie Connect's cross-device messaging. — [Components: Getting Started](https://www.protopie.io/learn/docs/components/getting-started), [Send and Receive Messages](https://www.protopie.io/learn/docs/components/send-receive-messages)

### 4.2 Beyond Figma

*(Framing caveat: the [ProtoPie vs. Figma](https://www.protopie.io/blog/protopie-vs-figma) post is marketing copy — cited only for direct quotes, cross-checked against technical docs where possible.)*

**Real functional inputs**: native Input layer type with actual device keyboard entry and typed keypads (text/URL/email/number/password). Form validation is built from Input triggers (Focus, Return) + Detect trigger reading the live Text property + Formulas — a documented validate-as-you-type pattern uses Focus (show error) + Detect (clear once valid). Tutorial-tier (not core-docs) sources: [Interactive Form Fields](https://www.protopie.io/blog/how-to-create-interactive-form-fields), [Form Fields with Conditional Logic](https://www.protopie.io/blog/rapid-prototyping-form-fields-using-conditions).

**Sensor access**: Tilt, Compass, Sound, 3D Touch, Proximity triggers; Camera (native layer + response) with QR/barcode scanning and matching predefined variables. Hardware beyond built-in device sensors goes through **ProtoPie Connect** plugins.

**Voice/speech** — explicitly labeled **Beta**. Requires microphone + internet; underlying STT/TTS vendor **not named**. **Multi-device — ProtoPie Connect**: "an extension for ProtoPie Studio that allows you to prototype real-world scenarios involving multiple devices, displays, hardware, and APIs seamlessly" — architecturally "a communication server connecting multiple clients," listening on port 9981 over localhost/LAN. Connects: ProtoPie on iOS/Android, ProtoPie in desktop browsers, hardware (Arduino, Logitech G29 wheel), external services (IFTTT webhooks, public APIs). Two connection modes: **ProtoPie Studio as hub** (all plans, Studio must stay open) or **ProtoPie Connect proper** (Pro/Enterprise, no need to keep Studio open), with deployment variants **Connect Desktop** (macOS/Windows) and **Connect Embedded** (Raspberry Pi etc., Enterprise-only). Concrete example in official docs: an automotive center-display triggering animations on the cluster and HUD. A **Smartwatch Solution** (marketing/solutions page, not core docs) describes phone-watch fitness sync, smartwatch smart-home control, and voice-driven smartwatch car control, requiring ProtoPie Player for Wear OS + Connect — flagged as solutions-tier, not confirmed in core reference docs. — [Connect: Getting Started](https://www.protopie.io/learn/docs/connect-getting-started), [Connecting Mobile Devices](https://www.protopie.io/learn/docs/connecting-devices/connecting-mobile-devices), [Smartwatch Solution](https://www.protopie.io/blog/protopie-smartwatch-solution)

## 5. Origami Studio and Rive

### 5.1 Origami Studio — patch-graph model

Currency: Origami Studio is actively maintained — latest release Version 223 (2026-07-07), with Versions 222/221 (Jun 23 / Jun 8, 2026) adding JS-patch and Shader-Layer LLM-generation integration. — [Origami releases](https://origami.design/releases/)

**Patches**: "the building blocks of Origami Studio" — designers "Add interaction, animation, and behavior to your prototype using blocks called patches." Each patch performs one discrete function and exchanges data with others. — [Patches](https://origami.design/documentation/patch-editor/patches), [Origami docs](https://origami.design/documentation/)

**Connections**: each patch has **ports** — inputs on the left, outputs on the right. **Cables** carry values one-directionally (output→input); an output port can fan out to multiple cables, but an input port accepts only one cable. Ports carry **typed values**: Number, Boolean, Text, Image, Video, Sound, Color, JSON, Point (2D/3D/4D). Patches can be grouped into reusable **Components**; graphs can be annotated with Comment patches; a Wireless Broadcaster/Receiver patch pair can pass values without a drawn wire. — [Patches](https://origami.design/documentation/patch-editor/patches), [Components](https://origami.design/documentation/workflow/components), [Patch Organization](https://origami.design/documentation/workflow/patchorganization)

**Patch categories** (per docs navigation): Animation (spring, bezier, bouncy), Logic (And/Or/Not, comparisons), Interaction (Tap, Drag, Scroll, Long Press, Double Tap, Keyboard, Hover, Pop Switch), Loops (array iteration/filtering — notably, Origami has native loop support where Figma does not), Math, Color, Data (JSON, Network Request, WebSocket), Device (camera, motion, location, haptics), Media, Shapes, Text, Utility (Delay, Counter, Random, Transition, Video), Layers (layer-bound patches incl. Material Design/iOS component sets). The core Interaction patch reports touch-down/tap plus position within its parent group and (on supported devices) 3D-Touch force; specialized variants exist for Scroll (with physics/paging), Pop Switch, Long Press, Double Tap, Drag, Keyboard, Hover. Layers must have opacity > 0 to receive touches. Any property in a layer's Inspector can be exposed as its own patch input/output by clicking it (the indirect "layer patch" mechanism — thinner source). — [Patches](https://origami.design/documentation/patch-editor/patches), [Interactions](https://origami.design/documentation/patch-editor/interactions), [Patch Organization](https://origami.design/documentation/workflow/patchorganization)

**Structural contrast with trigger/action and state-machine models**: Origami's core primitives are **state** ("a value that persists over time," e.g. a Switch holding on/off) and **pulse** ("On ✓ only for a single frame," used "to tell patches to perform an action" — a momentary event signal). Both travel over the same cables in the same dataflow graph; pulse-accepting ports can auto-derive a pulse from an off→on state change. This makes Origami's model a **continuously-evaluated dataflow/signal graph**: behavior emerges from how typed values propagate frame-by-frame through interconnected nodes, with no built-in "current state" enum or named-transition primitive — mode-like behavior is composed from ordinary patches (Switches, comparisons, logic). This is structurally different from a trigger→action model (discrete event mapped directly to discrete effect) and from an explicit state-machine model like Rive's, where the system is always in exactly one named state and moves only via defined transitions. — [Concepts: Pulse and Signal](https://origami.design/documentation/concepts/pulsesignal)

### 5.2 Rive

**Artboards**: the root container of a composition — "act[s] as the root of every hierarchy," defining dimensions and background color. A single `.riv` file can contain unlimited artboards, each independently loadable at runtime by name (e.g. `artboard: "Your_Artboard_Name"`), letting one binary package an entire icon set/asset library. Per-artboard Inspector properties: position, size, layout, fill, origin, render presets. — [Artboards](https://rive.app/docs/editor/fundamentals/artboards)

**State machines**: "a visual way to connect animations together and define the logic that drives the transitions." **States** are timeline animations that can play (e.g. Idle/Hovered/Clicked for a button); every artboard has at least one state machine by default. **Transitions** are a directional path (dragged connector-to-connector) plus path, conditions, properties, and actions; multiple transitions between the same state pair express OR logic. **Conditions** = source value + operator (equals/greater-than/less-than/etc.) + comparison value; sources can be View Model properties, Events, or built-in properties (artboard width/height/ratio); multiple conditions on one transition are **AND**-ed (use separate transitions for OR). **Transition properties**: Duration (0=instant), Exit Time (time or % of current state that must play first), Pause Source When Exiting, Allow Exit During Transition (interruptibility), Interpolation (easing curve), Randomize Exit (weighted random pick among outgoing transitions). — [State Machine](https://rive.app/docs/editor/state-machine/state-machine), [Transitions](https://rive.app/docs/editor/state-machine/transitions)

**Inputs — IMPORTANT CURRENCY FLAG**: as of the current docs (fetched 2026-07-20), the Inputs page carries an explicit deprecation notice: **"⚠️ DEPRECATED: Use Data Binding instead of Inputs for controlling Rive graphics"** / **"This entire page documents the legacy Inputs system... Data Binding is considered best practice since View Models are both more powerful and easier to control at runtime."** The UI has also moved — "Inputs now live in the Animations panel." The three legacy types (still functional, no longer recommended): **Boolean** (true/false, persists), **Trigger** (momentary, auto-resets after firing; runtime `SMITrigger`/`.Fire()`), **Number** (numeric; runtime `SMINumber`/`.Value`). This is a meaningful currency note — older tutorials/blogs likely still describe Inputs as primary, but current docs route new work through Data Binding/View Models instead. — [Inputs](https://rive.app/docs/editor/state-machine/inputs)

**Listeners**: translate runtime events into effects. Listen-to conditions: **Pointer Enter, Pointer Exit, Pointer Move, Pointer Down, Pointer Up, Click** (down+up within target), plus **View Model Property Change** and **Rive Event**. Note: Pointer Exit only fires while Rive can still read pointer position (may not fire on leaving via canvas/container edge). On trigger, a listener can change a View Model property, "Align Target" (object follows pointer), fire a Rive Event, or run other scripted actions — chainable, and can use bound data-binding values inside actions. — [Listeners](https://rive.app/docs/editor/state-machine/listeners)

**Data binding**: connects a **View Model** (typed schema — "position, scale, rotation, color, animation states") to a **View Model Instance** (live values) to scene properties — framed as "a contract between engineering and design: engineers push data to the contract, designers connect their UI to it." Property types a View Model can declare: **Number, String, Boolean, Color, Enum, Trigger, List, Image, Artboard**, and nested View Models. **Two-way binding confirmed**: "When data changes, your scene updates automatically. Likewise, changes made in your scene can be written back to your data." A **Data Converter** system transforms values in-flight between a View Model and target property (type converters, string trim/pad, math range-mapping/clamping, unit conversions like degrees→radians), chainable via "Group Converters" — this specific converter-detail level is sourced from a third-party technical reference (DeepWiki), not Rive's own docs directly, so treat as corroborated-but-secondary. — [Data Binding Overview](https://rive.app/docs/editor/data-binding/overview), [Data Binding in Rive (blog, Apr 15, 2025)](https://rive.app/blog/data-binding-in-rive-a-shared-language-for-designers-and-developers), converter detail: [DeepWiki](https://deepwiki.com/rive-app/rive-runtime/7.3-data-converters)

**Maturity/timeline**: Data Binding introduced **April 15, 2025**; progressed through community-announced milestones ("now available in Web Runtime," "now live for all users" — exact dates UNCONFIRMED, page timestamps unretrievable). On **July 17, 2025**, Rive shipped **Lists** (out of Early Access — dynamic virtualized UI generation from item sequences), **Images** (bind images to view-model properties, runtime-updatable), and **Artboards** (swap an artboard's source at runtime, preserving constraints/animations) as data-bindable types. Combined with Inputs now actively steering new projects toward Data Binding, this is Rive's current primary, GA, actively-expanding data model as of 2026 (~15 months old at time of writing). — [Data Binding announcement](https://rive.app/blog/data-binding-in-rive-a-shared-language-for-designers-and-developers), [community.rive.app: web runtime](https://community.rive.app/c/announcements/data-binding-now-available-in-web-runtime), [community.rive.app: GA for all users](https://community.rive.app/c/announcements/data-binding-is-now-live-for-all-users), [Lists/Images/Artboards (Jul 17, 2025)](https://rive.app/blog/data-binding-supercharged-lists-images-and-artboards)

**Caveat**: a direct fetch of `rive.app/changelog` returned a stale-looking snapshot (most recent entry claimed as Feb 28, 2025, no Data Binding mentioned), conflicting with the dated blog/community sources above and with web-search results showing active 2026 changelog entries (Unity state-machine work dated Jan 15, 2026; "Rive Agent" opened to free users Apr 30, 2026). Treat the changelog fetch as unreliable in this pass; the blog-post/docs timeline is more consistent. — [rive.app/changelog](https://rive.app/changelog)

**Where Rive is used in production**: Rive's own case-studies hub lists dated, named write-ups: **Spotify** (Wrapped 2025 interactive experience, Jan 9 2026), **LinkedIn** with design partner **BUCK** (first "Year in Review," "207,360 possible user journeys across three languages," Mar 4 2026, two entries), **Duolingo** (AI Video Call feature with character Lily, Mar 20 2025), **Dropbox** (interactive brand-guidelines site, Jan 17 2025), **Figma** (homepage relaunch, Jul 10 2023), **Intercom** (migrated from Lottie to Rive, Aug 5 2024), plus **CARS24, Kredivo, Melodics, Blynk, Megadeth Digital, Brilliant**, and others, each with a named dated write-up. — [Rive case studies](https://rive.app/blog/case-studies)

## Cross-cutting notes for the comparison

- **Figma's true "action" schema is 8 variants, not ~15** — the help-center's action list is a UI-level taxonomy layered over a much smaller discriminated union (`NODE` covers 5 of the "named" actions via its `navigation` field; `UPDATE_MEDIA_RUNTIME` covers 6 video sub-actions via its `mediaAction` field). This is the single most load-bearing data-model fact from the Figma research for a schema-level comparison.
- **Figma's variable-type story is currently in transition**: 4 types at the API/schema level (Boolean/Float/String/Color) vs. 6 named in the current UI (adding Timing/Easing, both tied to the newly-beta'd Figma Motion, June 2026). Don't treat "6 types" as the stable data model yet.
- **Rive's documented control surface changed underneath itself**: Inputs (Boolean/Trigger/Number) — long treated as Rive's primary state-machine control mechanism in tutorials — are now explicitly marked deprecated in Rive's own current docs in favor of Data Binding/View Models. Any older source describing Rive via Inputs alone is describing the legacy, not current-best-practice, model.
- **Google Stitch's fundamental interaction model changed** between May 2025 (linear chat-to-result, no canvas) and March 2026 (infinite canvas holding multiple linked artifacts, plus real click-through prototyping) — a bigger structural shift than a typical feature update.
- **Figma Make and Figma Design are deliberately non-interoperable**: Figma's own FAQ states there is no way to get a functional Make app inside Design, and no way for Design edits to flow back into Make — the two file types are one-directional and lossy (snapshot-as-static-layers only), not linked artifacts on a shared canvas.
- **Both Figma and ProtoPie converge on name/hierarchy-based layer matching** for their "auto-tween between two states" feature (Smart Animate / Smart Jump respectively) — same underlying matching strategy, same class of failure mode (rename or re-hierarchy breaks the match).
- Several "hard ceiling" claims about Figma (no real text input, no scroll-position logic, no loops, no live data binding) rely partly on absence-of-evidence reasoning or on forum threads that are 1–2+ years old relative to today (2026-07-20) and were not fully re-verified against 2026 release notes within the research budget — flagged individually above, but worth a final currency check before treating any of them as settled facts in a publication.
