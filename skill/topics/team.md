summary: team projects: sync, collisions, what travels, limits, history, git, linking a frame

A spool.json beside design/ ({ "project": "https://spool.page/<team>/<project>" }) makes design/ a local copy of a team project. Every save in it reaches the team's other editors through spool.page within about a second, and theirs arrive here as real files, so write frames exactly as anywhere else; a file a teammate changed since you read it is theirs now, so read it again before editing. If your save reaches the team after a teammate's to the same file, spool merges the two line by line and the merge lands in the file; only where both changed the same lines is yours set aside: the file takes the save that came first (a teammate's, or another copy of yours signed in as the same account) and yours is kept in design/.spool/set-aside/. The next project verb you run says so once, and `spool check` fails while it stands. Redo your change on top of the file and save it, which settles it, or settle it with `spool set-aside` (lists them), `spool set-aside mine <path>` (yours back over it, as a new save) or `spool set-aside theirs <path>` (let yours go). The person sees a count of them on the canvas with the same choices. Only canvas.json, AGENTS.md, CLAUDE.md, frames/** and shared/** travel; .spool/ and design/.gitignore stay on this machine. A file stays on this Mac, unsent, when it is outside those, a symlink, or over 25 MB, and while sync is paused on a limit (the team's design/ at 1 GB, or more saves than spool.page takes) or until Spool is updated (a teammate's newer Spool moved the team on; the line says how to update) what changes waits here; the next project verb you run on the project names each file that didn't travel and why, and the pause, once each, and `spool check` fails on every file that stays on this Mac each time it runs, until the file is moved, shrunk or gone. Scratch files (drivers, screenshots, notes) never go in design/. Spool never compresses anything: shrink media on this Mac before it goes in design/, choosing the quality on purpose, and check the size it came out at — video with ffmpeg (`ffmpeg -i in.mov -vf scale=-2:1080 -c:v libx264 -crf 28 -an out.mp4`: a higher crf or a smaller scale is smaller and blurrier), images by resizing and re-encoding (`sips -Z 2400 in.png` on a Mac, or `cwebp -q 80 in.png -o out.webp`). design/ is out of git there (its own .gitignore is `*`) and history never commits it: commit spool.json, never design/. Git never writes to the team's copy: whatever a checkout, pull, reset or merge puts in design/ is never sent, and the team's version comes back over what the team has, while a file the team never had stays as git left it, unsent, until someone edits it; a design/ that vanishes is refilled, not deleted for the team. A spool.json with no design/ beside it means run `spool open` there, which fetches it (so do check and the read verbs; skill doesn't). A repo with neither, where the team already works on its canvas from another checkout, takes `spool init --team <team>` at its root: init joins the repo's project and fetches its design/ (topic: projects). Moving an existing project into a team is the person's call: they do it in the app (Move to team…), or you run `spool move --team <address>` only once they said yes. It uploads design/ and makes the one commit `design: moved to Spool Cloud`, which also adds "design/ is a spool canvas: run `spool skill` before working there." to the repo's AGENTS.md, so never untrack design/ or write spool.json yourself. A team project moved to another team keeps syncing at its new address before anyone pulls the commit that rewrote its spool.json; one moved out of its team (or removed from it) stops syncing here and stays out of git until a pull brings design/ back, and waits 30 days in the team's trash, where an admin can restore it with its comments and shares; Get it then picks it up again. `spool move` does all these moves (topic: projects), only once the person said yes. The team history is every save to the project for 90 days, applied or set aside, kept by spool.page, not git: `spool history frames/<frame>/frame.tsx` lists a file's saves, newest first, and `--at <time>` prints the file as it stood at that time, or says it didn't exist then. The verb only reads; nothing it prints changes design/ until you write it there, and what you write is an ordinary save. To show someone a frame of a team project, link it: the project's address with ?frame=<frame> (its full name, encoded: https://spool.page/devosurf/shop?frame=checkout%2Fcart) opens that frame played, in a browser, for anyone in the team.
